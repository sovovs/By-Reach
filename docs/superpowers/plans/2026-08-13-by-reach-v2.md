# By-Reach v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `By-Reach 2.0.0b1` as a cleanly renamed Python distribution whose approved source executors fall back to byCLI and whose generic webpage path can only use `bycli web/read`, then integrate the immutable release commit into ByClaw.

**Architecture:** By-Reach owns a declarative executor-policy registry, a shell-free command runner, shared result validation, and byCLI capability discovery. The standalone package uses only `by-reach`/`by_reach`; ByClaw retains `agent-reach` solely as its stable Skill/database identifier while moving runtime commands and doctor output to By-Reach and `providers.byReach` schema version 2.

**Tech Stack:** Python 3.10-3.13, Hatchling, pytest, ruff, mypy, GitHub Actions, PyPI Trusted Publishing, OpenClaw Skill Markdown, Docker, unittest.

---

## File structure

### By-Reach repository

- `by_reach/executor_policy.py`: executor kinds, immutable executor specifications, channel policies, and the approved registry.
- `by_reach/executor_runtime.py`: bounded shell-free subprocess execution, output validation, fallback sequencing, and typed failures.
- `by_reach/bycli.py`: `bycli list -f json` parsing, read-capability checks, and generic webpage execution.
- `by_reach/channels/_bycli_site.py`: shared doctor implementation for byCLI-only website channels.
- `by_reach/channels/*.py`: channel recognition and source-specific availability checks backed by the central policy.
- `by_reach/skill/`: standalone `by-reach` Skill and references.
- `tests/test_public_identity.py`: breaking rename and packaging contract.
- `tests/test_executor_policy.py`: policy whitelist and forbidden-executor contract.
- `tests/test_executor_runtime.py`: fallback and result-validity semantics.
- `tests/test_bycli.py`: manifest validation and generic webpage execution.
- `tests/test_web_channel.py`: generic URL routing and SSRF rejection.
- `tests/test_skill_policy.py`: static Skill routing and stale-name contract.
- `.github/workflows/ci.yml`: Python/Windows/wheel gates.
- `.github/workflows/publish.yml`: tag-gated build, OIDC publish, and GitHub prerelease.

### ByClaw repository

- `middleware/openclaw/Dockerfile`: immutable By-Reach source install and verification.
- `middleware/openclaw/byclaw_capability_doctor.py`: schema version 2 and `providers.byReach`.
- `middleware/openclaw/skills/agent-reach/`: By-Reach public policy plus ByClaw overlay under the stable Skill ID.
- `middleware/openclaw/skills/bycli/SKILL.md`: By-Reach brand and routing boundary.
- `middleware/openclaw/skills/knowledge-collection/SKILL.md`: By-Reach brand while retaining `$agent-reach` routing ID.
- `deploy/middleware/initdb/04_dml.sql`: user-visible Skill name/description only; technical code remains `agent-reach`.
- `deploy/migrations/versions/V0.3.1/V0.3.1__dml.sql`: user-visible Skill name/description only.
- `middleware/openclaw/tests/test_*`: doctor, Skill, image, and stale-consumer contracts.
- `byclaw-be/src/test/java/com/iwhalecloud/byai/manager/connector/ConnectorSchemaTest.java`: display-name assertion while retaining the stable code.

- [ ] **Step 3: Implement immutable policy types and the approved registry**

```python
from dataclasses import dataclass
from enum import Enum


class ExecutorKind(str, Enum):
    CLI = "cli"
    MCP = "mcp"
    API = "api"
    LIBRARY = "library"
    BYCLI = "bycli"


@dataclass(frozen=True)
class ExecutorSpec:
    name: str
    kind: ExecutorKind
    capability: str
    terminal: bool = False


@dataclass(frozen=True)
class ChannelPolicy:
    channel: str
    executors: tuple[ExecutorSpec, ...]

    def __post_init__(self) -> None:
        if not self.executors:
            raise ValueError(f"{self.channel} requires at least one executor")
        if any(item.terminal for item in self.executors[:-1]):
            raise ValueError("only the final executor may be terminal")


def cli(name: str, capability: str) -> ExecutorSpec:
    return ExecutorSpec(name, ExecutorKind.CLI, capability)


def api(name: str, capability: str, *, terminal: bool = False) -> ExecutorSpec:
    return ExecutorSpec(name, ExecutorKind.API, capability, terminal=terminal)


def library(name: str, capability: str, *, terminal: bool = True) -> ExecutorSpec:
    return ExecutorSpec(name, ExecutorKind.LIBRARY, capability, terminal=terminal)


def bycli(capability: str) -> ExecutorSpec:
    return ExecutorSpec("bycli", ExecutorKind.BYCLI, capability, terminal=True)


POLICIES = {
    "web": ChannelPolicy("web", (bycli("web/read"),)),
    "twitter": ChannelPolicy("twitter", (cli("twitter-cli", "twitter"), bycli("twitter/search"))),
    "reddit": ChannelPolicy("reddit", (cli("rdt-cli", "rdt"), bycli("reddit/search"))),
    "bilibili": ChannelPolicy("bilibili", (cli("bili-cli", "bili"), bycli("bilibili/search"))),
    "facebook": ChannelPolicy("facebook", (bycli("facebook/search"),)),
    "instagram": ChannelPolicy("instagram", (bycli("instagram/search"),)),
    "linkedin": ChannelPolicy("linkedin", (bycli("linkedin/search"),)),
    "xiaohongshu": ChannelPolicy("xiaohongshu", (bycli("xiaohongshu/search"),)),
    "github": ChannelPolicy("github", (ExecutorSpec("gh CLI", ExecutorKind.CLI, "gh", terminal=True),)),
    "youtube": ChannelPolicy("youtube", (cli("yt-dlp", "yt-dlp"), bycli("youtube/search"))),
    "rss": ChannelPolicy("rss", (library("feedparser", "rss/read"),)),
    "exa": ChannelPolicy("exa", (ExecutorSpec("Exa via mcporter", ExecutorKind.MCP, "exa.web_search_exa", terminal=True),)),
    "xiaoyuzhou": ChannelPolicy("xiaoyuzhou", (library("transcription", "audio/transcribe"),)),
    "v2ex": ChannelPolicy("v2ex", (api("V2EX API", "v2ex/api"), bycli("v2ex/hot"))),
    "xueqiu": ChannelPolicy("xueqiu", (api("Xueqiu API", "xueqiu/api"), bycli("xueqiu/search"))),
}
```

The initial registry intentionally includes Exa as the one already-approved MCP-backed non-web search executor. The future-MCP test must therefore assert that the only enabled MCP capability is `exa.web_search_exa`, not that the registry contains no MCP entries.
